# 太玄经 · 会话占测使用指导方案

> 适用版本：wechat-miniprogram 卜卦页（`pages/divine`）+ 意图词库（`utils/intent-dict.js`）+ 类型库（`utils/taixuan-types.js`）
> 文档定位：一线开发者 / 维护者 / 内容运营均可直接照此文档使用、扩展与排查
> 输入语言：用户问句 ≤ 20 字 → 自动识别预测类型 → 起卦 → 解读 → 行动建议

---

## 一、目标与适用场景

### 1.1 一句话目标
让用户在小程序中 **用一句自然语言描述所问**（不超过 20 字），系统即可在 **不弹出类型选择器** 的情况下，**自动判断最合适的预测类型**，完成起卦并给出可读、可执行的解读。

### 1.2 适用场景
| 场景 | 用户输入示例 | 应识别类型 |
| --- | --- | --- |
| 失物寻回 | "我的羊丢了" | 33 失物寻回 |
| 求职面试 | "明天面试能否通过" | 1 求职应聘 |
| 升迁加薪 | "今年能涨薪吗" | 2 事业升迁 |
| 婚姻 | "和对象什么时候领证" | 13 婚姻婚配 |
| 健康 | "最近总失眠怎么办" | 22 身心调理 |

### 1.3 不适用场景
- 用户输入为空 / 纯表情 / 超过 20 字 → 不自动识别，按手动选择走
- 用户已 **手动选择** 过类型（`manuallySelected = true`）→ 不覆盖其选择
- 用户问句含 **敏感内容**（涉黄、政、血光具体细节）→ 走安全兜底，提示改用手动选择

## 三、词库使用规范

### 3.1 文件结构

```
wechat-miniprogram/utils/
├── intent-dict.js         // 主词库（多字词 + 单字词 + 匹配函数）
├── taixuan-types.js      // 40 种预测类型定义
├── taixuan-engine.js     // 起卦引擎
└── taixuan-data.js       // 81 首首辞、赞辞、测辞

tools/
└── intent-expand.js      // 词库自动扩张脚本（需 Node.js 14+）
```

### 3.2 词条登记规则

**多字词（主导命中）**
- 长度 2~6 字
- 语义与某个预测类型直接对应
- 形如：`'求职': [1]`
- 一词多类型时，形如：`'跳槽': [1, 2]`（既属"求职"又属"升迁"判断）

**单字词（仅做助攻）**
- 长度 1 字
- 一个类型 ≥ 20 个单字
- **绝不**独立顶起排序，只在多字词命中数相同时做"并列破局"
- 形如：`'试': [1, 9]`（试 → 既可指面试也可指考试）

### 3.3 排序算法

```javascript
// utils/intent-dict.js → matchTypes
// 主导排序：多字命中数
arr.sort((a, b) =>
  (b.multiCount - a.multiCount) ||   // ① 多字命中数优先
  (b.len - a.len) ||                 // ② 总词长（长词更精确）
  (b.singleCount - a.singleCount)    // ③ 单字仅作并列破局
)
```

**举例**

| 输入 | 命中详情 | 结果 |
| --- | --- | --- |
| "我的羊丢了" | 类型 33：多字 1(丢了) + 单字 1(丢) | 33 |
| "今天面试涨薪升职" | 类型 2：多字 2(升职/涨薪) + 单字 3(升/涨/薪)；类型 1：多字 1(面试) + 单字 3(职/面/试) | 2 优先 |
| "我 offer 入职了" | 类型 1：多字 2 + 单字 2 | 1 |

## 四、页面使用流程

### 4.1 入口

1. 底部 Tab 切换到 **"卜卦"**
2. 顶部模式选择切到 **"会话占测"**
3. 在输入框键入 ≤ 20 字问句

### 4.2 自动识别行为

| 触发 | 行为 |
| --- | --- |
| `bindinput` 每次文本变化 | `autoDetectType(text)` |
| 命中 0 个 | 清空 `autoHint`，保持"未选"状态 |
| 命中 1+ | 取 Top1(单模式) 或 Top2(复合模式)，写入选中态 + 顶部"已识别:XX" |
| 用户手动点选类型 | 标记 `manuallySelected = true`，后续输入不再自动覆盖 |

### 4.3 起卦

- 复合模式要求 2 个类型均确认
- 单一模式要求 1 个类型确认
- 起卦按钮 `canStartDivine()` 通过 → 调 `startDivine()` → 进入三变/四变动画 → 出结果

### 4.4 结果展示

每条记录保存字段：

```javascript
{
  id, time, timeStr,
  question,              // 用户原问句
  method, methodText,    // 揲蓍/硬币
  mode, modeText,        // 会话/单项/复合
  selectedTypeIds,
  selectedTypeNames,
  typeInterpretations,   // 每类型: {name, desc, interpretation, xuanRef}
  shouName, shouIndex, shouXuan, shouYinYang, shouPosition, shouCi,
  zanName, zanPosition, zanWuxing, zanDayNight, zanXiuJiu, zanCi, zanCe,
  biaoType, fortuneLevel, fortuneText, dayGanzhi
}
```

## 五、词库维护手册

### 5.1 新增一个预测类型

1. **类型注册** —— 在 `taixuan-types.js` 的对应 `CATEGORIES[i].types` 中追加：
   ```javascript
   { id: 41, name: '新类型', desc: '...', kw: '新' }
   ```
   注意 `id` 与 `COMPOSITE_PRESETS` 中复合类型不冲突

2. **多字词** —— 在 `intent-dict.js` 的 `WORD_TO_TYPE` 末尾追加 **≥ 20 个**
3. **单字词** —— 在 `SINGLE_BY_TYPE` 末尾追加 **≥ 20 个**

### 5.2 跑扩张脚本

```bash
cd tools
node intent-expand.js
```

会生成：
- `intent-expand.candidates.json`：按类型分组的合并候选词
- `intent-expand.report.md`：类型统计 + 共享词告警

### 5.3 一词多类型审查

`SYNONYM_GROUPS` 中的族是"任一词命中即全族并入" —— 加新词时：
- 同族词必须语义同构
- 不同族词不要在 `DISPUTED` 表里胡乱登记

### 5.4 质量自检三问

每次新加词后，回答：
1. **多字词是否覆盖 80% 用户说法？**（含口语 / 书面）
2. **单字词是否都是"该类型独特字"？**（避免"我/你/的"这种通用字）
3. **与其它类型是否会有歧义？**（歧义词进 `SYNONYM_GROUPS` 多类型）

## 六、排查手册

| 现象 | 可能原因 | 处置 |
| --- | --- | --- |
| 始终未识别 | 词库无任何命中 / 文本超过 20 字被截断 | 查 `matchTypes` 返回值；放宽 20 字限制或扩词 |
| 误识到其它类型 | 单字命中数顶到首位 | 把该单字从错配类型移除或加同义多字词 |
| 复合模式只显示 1 个 | 命中总数 < 2 | 在更多类型中补词，或在 UI 允许"未识别时手选第二个" |
| 起卦按钮一直灰 | `manuallySelected` 与识别状态不一致 | 切换到手动模式或重新输入 |
| `ReferenceError: zhou` | `browse.js` 等处对象简写错误 | 查 `{ zhou, ... }` 改为 `{ zhou: z, ... }` |
| 词库扩张报错 | `intent-dict.js` 缺新类型 | 先注册类型，再扩词 |

## 七、合规与边界

1. **可复现性**：相同问题、相同时间、相同方法 → 同结果，契合占卜"可复现所主"原则
2. **离线优先**：词库纯本地计算，无网络请求；扩展工具脚本仅在维护时本地运行
3. **字数上限**：用户输入 ≤ 20 字；超长不识别，提示"请精简"
4. **无大模型依赖**：当前版本不接 LLM，词库是唯一入口
5. **隐私**：用户问句仅本地分析，不上送服务器
